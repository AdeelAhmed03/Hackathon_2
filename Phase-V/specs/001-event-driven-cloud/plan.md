# Implementation Plan: Event-Driven Cloud Todo Application

**Branch**: `001-event-driven-cloud` | **Date**: 2026-02-09 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/001-event-driven-cloud/spec.md`

## Summary

Phase V transforms the Todo application into an event-driven, cloud-native system with advanced task management features. The implementation adds recurring tasks with auto-spawn, due dates with exact-time reminders via Dapr Jobs API, priorities and tags with advanced search/filter/sort capabilities, and event-driven architecture using Kafka (Redpanda Cloud or Strimzi). Services communicate via Dapr Pub/Sub, with new microservices (notification-service, recurring-service) consuming events from Kafka topics. Deployment targets both local Minikube and cloud Kubernetes (Oracle OKE preferred, Azure AKS/GKE fallback) with GitHub Actions CI/CD.

## Technical Context

**Language/Version**: Python 3.13+ (backend services), TypeScript/Node.js 22+ (frontend)
**Primary Dependencies**: FastAPI, SQLModel, Cohere SDK, Dapr SDK, httpx (async HTTP), Next.js 16+, Tailwind CSS, Better Auth
**Storage**: PostgreSQL (via Helm chart), Kafka/Redpanda (event streaming), Dapr State Store (optional conversation persistence)
**Testing**: pytest (backend), Jest (frontend), integration tests with Testcontainers
**Target Platform**: Kubernetes (Minikube local, Oracle OKE/Azure AKS/GKE cloud)
**Project Type**: Web application (monorepo: frontend + backend + microservices)
**Performance Goals**: <500ms API response, <5s event-driven latency, <10s reminder precision, 100 concurrent users
**Constraints**: Oracle OKE Always Free tier limits (4500 hours/month, 2 OCPU, 12GB RAM), Redpanda Cloud free tier
**Scale/Scope**: 1000 tasks per user, 100+ concurrent users, 3 Kafka topics, 4 microservices

## Cohere Integration Pattern

### Tool Calling Adapter

```python
# backend/src/services/cohere_adapter.py
import cohere
from typing import Any

TOOL_PROMPT = """You are a task management assistant. Analyze the user's request and output a JSON object with the action to take.

Available actions:
- add_task: Create a new task
- list_tasks: List tasks with optional filters
- complete_task: Mark a task as completed
- update_task: Update task properties
- delete_task: Delete a task
- search_tasks: Search tasks by keyword

Output format (JSON only, no explanation):
{"action": "<action_name>", "params": {<action_parameters>}}

For add_task, params include: title, description, priority (low/medium/high), tags (array), due_at (ISO8601), remind_at (ISO8601), recurring_interval (daily/weekly/monthly/yearly)
For list_tasks, params include: priority, tags (array), status, search, sort_by, sort_order
For update_task, params include: task_id, and any fields to update
For complete_task, params include: task_id
For delete_task, params include: task_id
For search_tasks, params include: keyword, priority, tags

User request: {user_message}
"""

class CohereToolAdapter:
    def __init__(self, api_key: str):
        self.client = cohere.Client(api_key)

    async def decide_action(self, user_message: str) -> dict[str, Any]:
        response = self.client.chat(
            message=TOOL_PROMPT.format(user_message=user_message),
            model="command-r-plus",
            temperature=0.1,
        )
        # Parse JSON from response
        import json
        return json.loads(response.text)
```

## Local Deployment (Minikube + Strimzi)

### Setup Script

```bash
#!/bin/bash
# scripts/minikube-setup.sh

# Start Minikube
minikube start --cpus=4 --memory=8192 --driver=docker

# Enable addons
minikube addons enable ingress
minikube addons enable metrics-server

# Install Dapr
dapr init -k --wait

# Install Strimzi Kafka Operator
kubectl create namespace kafka
kubectl apply -f "https://strimzi.io/install/latest?namespace=kafka" -n kafka

# Wait for Strimzi operator
kubectl wait --for=condition=ready pod -l name=strimzi-cluster-operator -n kafka --timeout=300s

# Apply Kafka cluster (KRaft mode, no Zookeeper)
kubectl apply -f dapr-components/strimzi/kafka-cluster.yaml -n kafka

# Wait for Kafka
kubectl wait kafka/kafka-cluster --for=condition=Ready -n kafka --timeout=300s

# Apply Dapr components
kubectl apply -f dapr-components/kafka-pubsub-local.yaml
kubectl apply -f dapr-components/kubernetes-secrets.yaml

# Deploy services
helm install postgres ./charts/postgres
helm install todo-backend ./charts/todo-backend
helm install notification-service ./charts/notification-service
helm install recurring-service ./charts/recurring-service
helm install todo-frontend ./charts/todo-frontend

echo "Setup complete! Access via: minikube service todo-frontend"
```

## Cloud Deployment (Oracle OKE)

### Setup Steps

1. **Oracle Cloud Account**
   - Sign up at oracle.com/cloud/free
   - Credit card required for verification (no charges for Always Free)
   - Region: Choose closest with Always Free availability

2. **Create OKE Cluster**
   ```bash
   # Via OCI Console:
   # Developer Services → Kubernetes Clusters → Create Cluster
   # - Quick Create
   # - Shape: VM.Standard.E2.1.Micro (Always Free)
   # - Nodes: 2

   # Configure kubectl
   oci ce cluster create-kubeconfig \
     --cluster-id <cluster-ocid> \
     --file ~/.kube/config-oke \
     --region <region>

   export KUBECONFIG=~/.kube/config-oke
   kubectl get nodes
   ```

3. **Redpanda Cloud Setup**
   - Sign up at redpanda.com/cloud
   - Create serverless cluster (free tier)
   - Create topics: task-events, reminders, task-updates
   - Get bootstrap servers and SASL credentials
   - Create Kubernetes secret:
   ```bash
   kubectl create secret generic redpanda-secrets \
     --from-literal=sasl-password=<your-password>
   ```

4. **Deploy with Helm**
   ```bash
   # Install Dapr
   helm repo add dapr https://dapr.github.io/helm-charts/
   ```

## CI/CD Pipeline (GitHub Actions)

### Workflow Overview

```yaml
# .github/workflows/deploy.yaml
name: CI/CD Pipeline

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

env:
  REGISTRY: ghcr.io
  IMAGE_PREFIX: ${{ github.repository }}

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.13'
      - name: Run backend tests
        run: |
          cd backend && pip install -r requirements.txt && pytest
      - name: Run frontend tests
        run: |
          cd frontend && npm ci && npm test

  build:
    needs: test
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write
    strategy:
      matrix:
        service: [backend, frontend, notification-service, recurring-service]
    steps:
      - uses: actions/checkout@v4
      - name: Build and push ${{ matrix.service }}
        uses: docker/build-push-action@v5
        with:
          context: ./${{ matrix.service }}
          push: true
          tags: ${{ env.REGISTRY }}/${{ env.IMAGE_PREFIX }}/${{ matrix.service }}:${{ github.sha }}

  deploy-staging:
    needs: build
    if: github.ref == 'refs/heads/develop'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Deploy to staging
        run: |
          echo "${{ secrets.KUBECONFIG_STAGING }}" > kubeconfig
          export KUBECONFIG=kubeconfig
          helm upgrade --install todo-backend ./charts/todo-backend \
            --set image.tag=${{ github.sha }} \
            --namespace staging

  deploy-production:
    needs: build
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    environment: production
    steps:
      - uses: actions/checkout@v4
      - name: Deploy to production
        run: |
          echo "${{ secrets.KUBECONFIG_PRODUCTION }}" > kubeconfig
          export KUBECONFIG=kubeconfig
          helm upgrade --install todo-backend ./charts/todo-backend \
            --set image.tag=${{ github.sha }} \
            --namespace production
```
